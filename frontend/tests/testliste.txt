# ── Frontend-Testliste (FE-TEST-1) ──────────────────────────────────────────
# Ein Glob-Muster pro Zeile. Ausgeführt wird die Liste im Frontend-Stage der
# `backend/Dockerfile`:
#
#     node --test <alle Muster dieser Datei> --test && npm run build
#
# Diese Datei ist die EINZIGE Stelle, an der neue Node-Tests eingetragen
# werden. Früher stand die Liste als eine lange Zeile im Dockerfile; jede
# Karte musste dort dieselbe Zeile ändern → ständige Merge-Konflikte.
#
# ── Neuen Test eintragen ───────────────────────────────────────────────────
# Eine Zeile mit dem Glob-Muster anhängen (z. B. `tests/<karte>-*.test.mjs`),
# die Testdatei selbst unter `frontend/tests/` bzw. `frontend/src/` ablegen.
# Kein Dockerfile-Eingriff mehr nötig.
#
# ── Regeln ─────────────────────────────────────────────────────────────────
# * `#` am Zeilenanfang = Kommentar, Leerzeilen werden übersprungen.
# * Muster sind GLOBS, keine Regexps; geprüft wird ab `frontend/`
#   (Build-Verzeichnis /build, lokal `cd frontend`).
# * Ein Muster muss mindestens eine Datei treffen. Muster, die ins Leere
#   laufen, und Testdateien, die von KEINEM Muster erfasst werden, meldet der
#   Wächter `tests/fetest1-testliste.test.mjs` im Build.
# * `.gitattributes` setzt `merge=union` für diese Datei: beim Merge werden
#   die Zeilen beider Seiten zusammengeführt, statt zu kollidieren.
#
# ── Gezielte Auswahl (schneller Build) ─────────────────────────────────────
# Eine eigene Datei mit wenigen Mustern übergeben, z. B.
#
#     frontend/tests/.auswahl.txt        (in .gitignore, nicht committen)
#     docker build -f backend/Dockerfile --build-arg \
#         NODE_TESTLISTE=tests/.auswahl.txt -t diakronos-<karte>:test ..
#
# Eine LEERE Auswahl bricht absichtlich ab: `node --test` ohne Argumente
# würde sonst selbst alle Tests im Verzeichnis suchen — dann liefe „nichts
# ausgewählt“ als „alles“ und der Abbruch bliebe unbemerkt.
#
